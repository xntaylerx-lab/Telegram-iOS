# Visual Quote — журнал решений

Каждое решение: что выбрано, почему, что было альтернативой. Новые записи добавляются снизу.

## M0 — Окружение (2026-10-12)

### D-001. Клон живёт в `~/Developer/Telegram-iOS`, ветка `visual-quote`
Причина: в пути `~/Documents/Telegram contest` есть пробел, Documents может синхронизироваться с iCloud. Так задано в задании (раздел 4).

### D-002. Сборка для симулятора через `Make.py build` с фиктивной подписью из `build-system/fake-codesigning`
Выбрано из двух допустимых путей задания (`generateProject --disableProvisioningProfiles` или `build` с fake-codesigning).
Причина: `build` даёт готовый `bazel-bin/Telegram/Telegram.ipa`, на который завязан штатный workflow обновления приложения в симуляторе из `CLAUDE.md` репозитория (копия `.app` из `.ipa`). Для `generateProject` нужен Xcode-проект и сборка через xcodebuild, а путь Xcode-managed signing требует настоящий Apple team.
Команда (из корня клона):
```
python3 build-system/Make/Make.py --cacheDir="$HOME/telegram-bazel-cache" build \
  --configurationPath="$HOME/Developer/telegram-config/build-config.json" \
  --codesigningInformationPath=build-system/fake-codesigning \
  --buildNumber=1 --configuration=debug_sim_arm64
```

### D-003. Конфиг сборки — копия в `~/Developer/telegram-config/build-config.json` с `team_id = C67CF9S4VU` и `bundle_id = ph.telegra.Telegraph`
Причина: `Make.py` отбирает provisioning-профили по точному префиксу `team_id.bundle_id` в `application-identifier` профиля (`BuildConfiguration.py`, `copy_profiles_from_directory`). Профили в `fake-codesigning` выписаны только на `C67CF9S4VU.ph.telegra.Telegraph`; при другом `bundle_id`/`team_id` ни один профиль не подходит, `aps-environment` не находится и сборка завершается с ошибкой до запуска Bazel.
Оригинальный `config/build-config.json` в папке проекта не изменён; изменённая копия лежит вне репозитория и вне git. Ключи api_id/api_hash в репозиторий не попадают: `build-input/*` в `.gitignore`.
Статус: ждёт подтверждения Ники (bundle id совпадает с официальным Telegram; для симулятора это безопасно, для распространения — нет).

### D-004. Для Xcode 26 нужен отдельный компонент Metal Toolchain
Факт: первая сборка упала на `MetalCompile` с ошибкой `cannot execute tool 'metal' due to missing Metal Toolchain`. Компонент скачан командой `xcodebuild -downloadComponent MetalToolchain` (688 МБ). Это обязательный шаг при настройке окружения с нуля — записать в README.

### D-005. Тестовое окружение Telegram (test DC)
Факт из кода: клиент поддерживает test DC только через аргумент запуска `--ui-test` (`AppDelegate.swift`, `isUITest`). В этом режиме используется отдельная папка данных `telegram-ui-tests-data`, которая **стирается при каждом запуске**, и регистрация идёт на тестовые серверы. Тестовые номера `99966XYYYY` (страна `+999`), код подтверждения — цифра DC пять раз (`docs/ui-testing.md`).
Проверено на симуляторе: при запуске с `--ui-test` клиент подключается к тестовым DC (149.154.167.40, 149.154.175.10, 149.154.175.117), без флага — к продакшн-адресам. Отдельного переключателя в Debug Settings нет. Следствие: без небольшой правки кода тестовый аккаунт не переживает перезапуск приложения. Решение, как вести разработку (реальные аккаунты или test DC с правкой), — за Никой после M0.

### D-006. Разработка ведётся на тестовых серверах Telegram (test DC), не на реальных аккаунтах
Решение Ники (2026-10-12). Причины: не нужен реальный номер и нет риска ограничения аккаунта, зарегистрированного через неофициальную сборку; фейковых персонажей для демо можно завести как отдельные тестовые аккаунты с именами и аватарками.
Как запускать: оба симулятора — с аргументом `--ui-test` (отправитель через XcodeBuildMCP `launch_app_sim` с `launchArgs`, получатель через `xcrun simctl launch <udid> ph.telegra.Telegraph --ui-test`).
Открытый вопрос на M1: нужна ли маленькая правка, чтобы тестовый логин не стирался при каждом запуске (`AppDelegate.swift` удаляет `telegram-ui-tests-data` при старте с `--ui-test`).
Реальные аккаунты понадобятся не раньше M3, для проверки вида сообщения в обычном Telegram.

### Заметка к D-006 (2026-10-12, вечер). Тестовые серверы отвергают фиксированный код
Факт: с нашим api_id `auth.sendCode` на test DC проходит (сервер отвечает `sentCodeTypeSms(length: 5)`, миграция между DC1–DC3 работает), но `auth.signIn` с кодом `XXXXX` возвращает `400: PHONE_CODE_INVALID` на всех трёх DC. Проверено через экран входа и через headless-путь репозитория (`--ui-test --delete-test-account <номер>`, без push-токена) — результат одинаковый. Собственный UI-тест репозитория (`Telegram/Tests/Sources/UITests.swift`) использует тот же сценарий с api_id команды Telegram. Единственная оставшаяся переменная — наш api_id. Логи приложения содержат api_hash открытым текстом: не пересылать их никому.
Статус: открыто. Варианты: проверить «Test configuration» для приложения на my.telegram.org/apps; попробовать повторную отправку кода звонком; откатиться на реальные аккаунты (риск описан в D-006).

### D-007. Переход на реальные аккаунты (отменяет D-006)
Решение Ники (2026-10-12, вечер). Причина: тестовые серверы отвергают фиксированный код с нашим api_id (см. заметку к D-006), повлиять из кода нельзя. Оба симулятора запускаются без `--ui-test`: отправитель через XcodeBuildMCP `launch_app_sim` без аргументов, получатель через `xcrun simctl launch <udid> ph.telegra.Telegraph`. Данные теперь в обычной папке `telegram-data` и переживают перезапуск. Риск ограничения свежего аккаунта принят осознанно.

## M2 — Выделение у отправителя (2026-10-12, вечер)

### D-008. Выделение строится на `ImageObjectSeparation`, подсветка — свой оверлей в новом модуле `VisualQuote`
Причина: в клиенте уже есть вырезание объекта для стикеров (Vision на устройстве, CoreML-модель `u2netp` в симуляторе), новый код его только вызывает. Обводка из `StickerCutoutOutlineView` не переиспользована: она с частицами и завязана на экран редактора; вместо неё подсветка считается из маски фильтрами CoreImage (два варианта: свечение и обводка). Точки встраивания: хук `contentLongTapAction` в `ZoomableContentGalleryItemNode` (3 строки) и секция в `ChatImageGalleryItemNode`. Флаг `visualQuote` в Debug Settings, в нашей сборке включён по умолчанию.

### D-009. Два подводных камня симулятора, оба обойдены внутри `VisualQuote`
1. CoreML-путь `ImageObjectSeparation` масштабирует маску обратно по `image.size` в поинтах; картинка галереи имеет `scale = 3`, поэтому маска получалась втрое меньше и смещалась. Решение: детектор передаёт копию изображения со `scale = 1`. На устройстве (путь Vision) проблемы нет; в upstream-код не лезем.
2. Маска после `CISharpenLuminance` в живом графе CoreImage выходит за 0…1, из-за чего инверсия и умножение давали яркую полосу по контуру и «пелену» по всему кадру. Решение: `CIColorClamp` на входе и перерисовка результата в премультиплицированный CGContext перед отдачей в слой.
Следствие для демо: в симуляторе модель выделяет один «главный» объект на фото (на снимке с тыквами — всю группу оранжевых), при касании вне него срабатывает кольцо. Поэлементное выделение — только на iPhone.

### D-010. Интерактивные проверки в симуляторе
В XcodeBuildMCP этой сессии нет инструментов нажатий. Для тапов и удержаний используется встроенный в Claude Code инструмент iOS Simulator (не `cliclick`/`osascript`/`screencapture`). Скриншоты экранов с личной перепиской в отчёты не попадают.

- Место кнопки «Reply»: сейчас стеклянная кнопка под выделением; альтернатива — в нижней стеклянной панели галереи.

### D-011. Выделение — редактируемая рамка, а не контур объекта (решение Ники, 2026-10-13)
Вместо свечения/обводки по маске показывается рамка с уголками, как в кадрировании фото в редакторе Telegram (размеры уголков и зон захвата взяты из `TGPhotoCropAreaView`): остальное фото затемняется, уголки тянутся, рамка двигается целиком, пока она активна — зум и прокрутка фото выключены. Vision только предлагает рамку по умолчанию вокруг найденного объекта; если объекта нет, рамка ставится вокруг точки касания.
Причины: это прямой родственник текстовой цитаты (выделение правится ручками); по сети уходит только прямоугольник, значит отправитель и получатель видят одно и то же; польза не зависит от качества распознавания и одинакова в симуляторе и на устройстве. Код свечения/обводки удалён из модуля (остался в истории git, коммит a0a6f55f85).
